## 修复:dev 启动报错 "Cannot assign to o because it is a constant"

**现象**:`npm run dev` 启动后 esbuild 报错,指向 android 目录旧构建产物 `android/app/src/main/assets/public/static/js/deviceStore-8644b845.js`(及 build/intermediates 副本),"Build failed with 1 error"。

**根因(两层)**:
1. Vite 3 的依赖预扫描(optimizeDeps)默认把项目内**所有 `.html` 文件**(排除 node_modules)当扫描入口。项目根下混有 android/、build-electron/ 等目录的旧产物 HTML,其中 `android/app/src/main/assets/public/index.html`(7月6日 cap sync 旧拷贝)引用了旧 bundle → 一路解析到 deviceStore 旧产物。
2. 旧产物中 `const o = window.JsFunction.toDevice(v); ... o = JSON.parse(...)[0].data || o` 对 const 重新赋值,esbuild 在 **bundle 模式**下该问题从 warning 升级为 **error**(transform 模式仅 warning)。
3. 源码源头:`src/store/deviceStore.js` sendCommand 中 `const order = ...; order = parsed[0]?.data || order`(const 重新赋值,运行时隐患)。

**修复**:
- `vite.config.js`:新增 `optimizeDeps.entries: [resolve(__dirname, 'index.html')]`,只扫描项目自身入口 HTML。
- `src/store/deviceStore.js`:sendCommand 中 `const order` → `let order`。

**验证**:dev 启动干净,0 报错。

**遗留**:android/app/src/main/assets/public 下旧产物仍含 const bug 代码,但不影响 dev;下次 `npm run pro` 构建 + `npx cap sync` 会覆盖。若再遇到,检查 optimizeDeps.entries 是否还在。

## 改造:火柴人模型 2D 线条 → 3D 体积化

**背景**:用户要求把火柴人模型改为 3D。排查发现 `renderMode: "model"` 依赖的 `/stickman.glb` 在项目中**不存在**;首页实际用 `skeleton-mode="stickman"` 平面线条模式(LineSegments2 + 平面头圆盘)。

**方案**(不依赖外部 GLB,自包含):改 `src/rendering/StickmanScene.js`:
- 肢体(12 条 COCO 骨架边):三个 InstancedMesh(chest/arms/legs),单位 CylinderGeometry(1,1,1,12),每帧按实例矩阵放置——position=线段中点、quaternion 由 (0,1,0) 对齐线段方向、scale=(半径,长度,半径)。半径:chest 0.045 / arms 0.028 / legs 0.036。
- 头部:平面圆盘 → 球体(r=0.11)+ 白色鼻尖小球(r=0.022,局部 +Y),quaternion 对齐 computeHeadPose 的 forward,保留朝向指示。
- 关节球:0.025 → 0.05,MeshBasicMaterial → MeshLambertMaterial(受光照、可投影)。
- 关键坑:InstancedMesh 必须 `frustumCulled = false`,否则包围球基于原点单位几何,实例会被视锥误剔除。
- 删除 LineSegments2/LineSegmentsGeometry/LineMaterial 导入;`stickmanMap` 条目字段改为 `limbMeshes`/`headSphere`/`_limbDummy`(对外键名 `stickmanLines` 保留,兼容 setSkeletonVisible/dispose)。
- 距离标签(CSS2D 绿色 m 标)逻辑未动。

**验证**:`npx vite build --mode pro --outDir dist-verify` 通过。注意直接 build 到默认 outDir 会触发 safe-delete 拦截(www/controllPage/html/static 90 个旧文件 > 50 阈值),需换 outDir 或分批处理。
