# AI感知雷达数据格式

---

## 1. 对接说明

本文档用于描述Inchi AI感知雷达数据结构及对接步骤。其中，骨骼、轨迹数据报文采用websocket+json的方式进行传输，详见雷达数据格式。其他报文可采用post+json的http协议进行对接。雷达的数据（包括数据+信令）都会经过云平台进行转发。

采用本方式对接，可以获取实时雷达数据流和跌倒告警信号。

---

## 2. 对接方法及API

### 2.1必要条件

1. 该雷达须在平台中创建过，即已经接入到平台中了，在客户端或小程序中显示在线。
2. 该雷达的设备ID已经明确。

### 2.2登录获取token接口

通过手机号(或账号或邮箱三者其一)和密码可获取token。该token暂时有效时间24小时。

POST请求：https://mmradar.inchitech.com/api/manage/user/getVideoToken

API请求参数格式:

```json
{
  "phone": "15*****939",   #手机号
  "email": "2*******2@mail.com",   #邮箱
  "username": "王**",   #账号
  "password": "19*****0"   #密码
}
```

通过账号密码获取token的API响应：

```json
{
    "code": 200,
    "message": "登录成功",
    "data": {
        "privileges": 0,
        "phone": "15*****930",  #手机号
        "name": "王**",  #用户名
        "id": 116,   #用户id
        "token": "11debe3d-a1c3-49c4-980d-9fc6d3d578e8",  #token
        "email": null #邮箱
    }
}
```

### 2.3验证token是否有效

通过该接口可以验证获取的token是否有效，如无效需重新获取。

POST请求：https://mmradar.inchitech.com/api/manage/user/validateToken

API请求参数格式：

```json
{
    "token": "a9a70cc1-5322-4b27-8f1b-bc42e089e071"
}
```

验证token是否有效接口API响应：

有效提示：

```json
{
    "code": 200,  #状态码
    "message": "token有效",  #提示信息
    "data": {
        "token": "a9a70cc1-5322-4b27-8f1b-bc42e089e071",  #token
        "valid": true #是否有效，true是有效
    }
}
```

无效提示：

```json
{
    "code": 401,
    "message": "token无效或已过期",
    "data": null
}
```

### 2.5雷达数据流对接地址及接口协议

实时数据媒体流：https://mmradar.inchitech.com/v2/ws/。该地址为websocket地址，对接前需要先行连接成功。连接成功后可以发送数据请求报文：

```json
{
    "startTime": "",      //开始时间，为空即可
    "endTime": "",       //结束时间，为空即可
    "content": "start",    //请求开始标志
    "deviceID": "A1************U2H2",      //设备ID
    "type": "2",            //请求类型，固定为2
    "session": "1744696377875",    //session，随机生成即可
    "deviceID1": "",        //为空
    "deviceID2": "",         //为空
    "scene": "",           //为空
    "multiradar": ""       //为空
    "token": ""     //token
}
```

请求成功后的回复报文如下：

```json
{
    "code":200,
    "message":"succeed"
}
```

请求成功后云平台即可在该websocket信道上发送数据流到请求客户端。其中每个Websocket报文为一个json格式的数据，包含了当前时刻雷达的骨骼和轨迹数据（详见雷达数据格式）。

注：结束浏览时可直接断开websocket连接而无需发送结束报文。

### 2.6跌倒告警查询

该消息为http+post格式，通过请求获取当前雷达的告警信息，再通过json格式返回，详见以下格式。

## 3. 雷达数据格式

### 1. 数据输出格式

雷达通过 WebSocket + JSON 方式输出实时数据流，也可通过 HTTP POST + JSON 进行事件数据上报。

正常情况下雷达每 50ms 输出一次数据（约 20Hz）。

在网络波动、系统负载或处理延迟情况下可能出现数据中断，需要通过 TimeStamp 判断连续性。

#### 1.1 输出方式

- 数据格式: JSON
- 编码: UTF-8

#### 1.2 完整JSON数据结构

```json
{
  "RadarParams": {
    "radarHeight": 2.5,
    "downtAngle": 15.0,
    "radarRoll": 0.0,
    "radarAzimuth_room": 0.0,
    "radarX_room": 0.0,
    "radarY_room": 0.0,
    "deltaX_room": 10.0,
    "deltaY_room": 8.0
  },
  "kpts": [
    [
      [1.2, 1.3, 1.4],
      [2.1, 2.2, 2.3],
      [0.8, 0.9, 1.0]
    ]
  ],
  "track_pos": [
    [1.5, 2.3],
    [2.1, 3.4]
  ],
  "track_id": [1, 2],
  "action": [1, 2],
  "Dis2Radar": [3.2, 4.1],
  "Tcalc": 0.05,
  "Tdatacap": 0.1,
  "TimeStamp": 1640995200000,
  "RadarID": "RADAR_001",
  "rawpc": "",
  "rawmmpc": ""
}
```

### 2. 字段详细说明

#### 2.1 kpts（骨骼关键点）

**RadarParams 参数表：**

| 字段名 | 类型 | 单位 | 说明 | 示例值 |
|--------|------|------|------|--------|
| radarHeight | float | 米 | 雷达安装高度 | 2.5 |
| downtAngle | float | 度 | 雷达下倾角 | 30.0 |
| radarRoll | float | 度 | 雷达横滚角 | 0.0 |
| radarAzimuth_room | float | 度 | 雷达方位角 | 90.0 |
| radarX_room | float | 米 | 雷达在房间坐标系X位置 | 0.0 |
| radarY_room | float | 米 | 雷达在房间坐标系Y位置 | 0.0 |
| deltaX_room | float | 米 | 房间X方向尺寸 | 5.0 |
| deltaY_room | float | 米 | 房间Y方向尺寸 | 5.0 |

- 类型: kpts 为三维数组，表示每条轨迹的人体关键点坐标。
- 格式: `[[[x坐标数组], [y坐标数组], [z坐标数组]]]`
- 说明: 每个轨迹的人体关键点3D坐标
- 坐标单位: 米
- 坐标系: 房间坐标系

骨骼点采用 COCO 17点定义：

| 序号 | 关键点 |
|------|--------|
| 0 | Nose |
| 1 | Left Eye |
| 2 | Right Eye |
| 3 | Left Ear |
| 4 | Right Ear |
| 5 | Left Shoulder |
| 6 | Right Shoulder |
| 7 | Left Elbow |
| 8 | Right Elbow |
| 9 | Left Wrist |
| 10 | Right Wrist |
| 11 | Left Hip |
| 12 | Right Hip |
| 13 | Left Knee |
| 14 | Right Knee |
| 15 | Left Ankle |
| 16 | Right Ankle |

示例:

```json
"kpts": [
  [
    [1.2, 1.3, 1.4, 1.5],  // X坐标数组
    [2.1, 2.2, 2.3, 2.4],  // Y坐标数组
    [0.8, 0.9, 1.0, 1.1]   // Z坐标数组
  ]
]
```

#### 2.2 track_pos（轨迹位置）

- 类型: 二维数组
- 格式: `[[x, y], [x, y], ...]`
- 说明: 每个轨迹的中心位置坐标
- 坐标单位: 米
- 坐标系: 房间坐标系

示例:

```json
"track_pos": [
  [1.5, 2.3],  // 轨迹1的中心位置
  [2.1, 3.4]   // 轨迹2的中心位置
]
```

#### 2.3 track_id（轨迹ID）

- 类型: 整数数组
- 说明: 每个轨迹的唯一标识符。注意：track_id不一定等于人数。
- 范围: 1-65535
- 特点: 同一轨迹在不同时刻保持相同ID

示例:

```json
"track_id": [1, 2, 3]
```

#### 2.4 action（动作识别）

- 类型: 整数数组
- 说明: 每个轨迹的动作类型

动作类型定义:

| 值 | 动作名称 | 说明 |
|----|----------|------|
| 0 | 走动 | |
| 1 | 跑步 | |
| 2 | 站着 | |
| 3 | 挥手 | |
| 4 | 坐着 | |
| 5 | 起身 | |
| 6 | 下蹲 | |
| 7 | 跌倒 | |
| 8 | 躺着 | |

示例:

```json
"action": [1, 4, 7]
```

#### 2.5 Dis2Radar（距离雷达距离）

- 类型: 浮点数组
- 单位: 米
- 说明: 表示每个轨迹到雷达的直线距离
- 精度: 0.1米

示例:

```json
"Dis2Radar": [3.2, 4.1, 2.8]
```

#### 2.6 时间与设备字段

| 字段名 | 类型 | 单位 | 说明 | 示例值 |
|--------|------|------|------|--------|
| Tcalc | float | 秒 | 算法计算耗时 | 0.05 |
| Tdatacap | float | 秒 | 数据采集时间间隔 | 0.1 |
| TimeStamp | uint64 | 毫秒 | Unix时间戳 | 1640995200000 |
| RadarID | string | | 雷达设别ID | |

- 类型: 字符串
- 说明: 雷达设备的唯一标识符
- 格式: 自定义字符串
- 示例: "RADAR_001", "RADAR_ROOM_A"

### 3. 多目标数据匹配规则

说明：所有数组字段通过相同索引进行匹配。

track_id[i]、track_pos[i]、kpts[i]、action[i]、Dis2Radar[i] 表示同一轨迹。

### 4. 点云数据格式

说明：rawpc 与 rawmmpc 为十六进制字符串格式的压缩点云数据。

每个点包含字段 [x,y,z,v,p]，每个字段2字节 int16，共10字节。

压缩规则：浮点数 ×1000 转换为 int16，小端序编码。

### 5. 数据中断与异常处理

当相邻 TimeStamp 差值明显大于 50ms 时，说明存在数据中断。

建议在应用层进行数据连续性检测和异常处理。

### 6. 坐标系定义（重要）

#### 6.1 房间平面坐标系（Room Coordinate System）

RadarParams 中的雷达位置和房间尺寸参数使用房间平面坐标系。

坐标系定义如下：

- 原点：房间上边界中间点
- X轴正方向：向右
- Y轴正方向：向下
- 适用字段：RadarParams 中的 radarX_room、radarY_room、deltaX_room、deltaY_room 等参数

#### 6.2 空间三维坐标系（Spatial Coordinate System）

骨骼点数据（kpts）以及轨迹位置数据（track_pos）使用空间三维坐标系。

空间坐标系与房间平面坐标系存在差异，其定义如下：

- 原点：(0,0,-1)，即房间平面坐标系原点上方1米位置
- X轴正方向：向下（对应房间平面坐标系Y方向）
- Y轴正方向：向右（对应房间平面坐标系X方向）
- Z轴正方向：向上

#### 6.3 坐标系关系说明

房间平面坐标系主要用于描述雷达安装位置和房间空间范围；空间三维坐标系用于描述人体骨骼点和轨迹在三维空间中的位置。

因此在使用数据时需要注意：RadarParams 中的坐标与 kpts / track_pos 中的坐标并不在同一坐标系下。

开发者在进行空间分析或可视化时，可能需要根据业务需求进行坐标转换。
